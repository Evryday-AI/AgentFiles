The standalone MIT application provides authenticated HTTP file handoff, scoped API keys, a browser interface, generic curl/Python examples, OpenAPI and a Markdown agent skill. Temporary files expire after seven days by default. Explicit persistence needs administrator policy and permission. Short codes require authentication; separate high-entropy links permit expiring, revocable public sharing.

One app process owns a dedicated PostgreSQL database and disk volume. Atomic keep/delete claims, bounded streamed uploads, capacity accounting and restart cleanup are tested with synthetic PostgreSQL/filesystem fixtures. Codes remain permanently reserved after metadata purge and restore; recovery without complete later-issuance evidence leaves uploads disabled. Follow [backups](../backups.md), [updates](../upgrading.md) and [retention](../retention.md). Experimental schema-2 rollback is a brief matched-snapshot read check; continued operation uses current schema 4 and complete reservation recovery.

## Preparation installation

Follow [setup](../setup.md) and [self-hosting](../self-hosting.md), using Docker with Linux containers, new credentials and dedicated volumes. The setup tool needs no host Node; source verification needs Node 24/npm. Normal stop/update commands preserve volumes. Preserve the MIT license, npm/browser/native notices and the image's Node/npm/Debian license files when distributing. No paid account, agent framework or telemetry service is required.

## Support scope and remaining gates

Windows x64 source checks, Docker Desktop Linux amd64 runtime checks and Windows Chromium viewports have local evidence. These are the candidate validation targets. Native Linux/macOS hosts, arm64, other browsers and physical devices remain untested. Local-CA Chromium checks support proxy/cookie policy but do not prove reachable public HTTPS or physical-phone behavior. No prior released-version upgrade is claimed.

Managed hosting/billing, shared customer tenancy, replicas, native CLI/MCP packaging, range/resumable transfers, transcoding and first-download deletion are deferred. No registry has been selected; no release publication workflow is prepared with guessed destinations.

Before source publication, review the exact final commit and recreated source archive/checksums. The tested implementation revision and later evidence-only revision are distinct; the image/SBOM retain their actual frozen candidate binding. The exported Linux amd64 image is a private validation artifact: its GPL/LGPL corresponding-source delivery arrangement remains an additional binary-publication gate. Installed build trees, build-stage images and the optional lzma native compiler binary must not be distributed while their embedded attribution is unresolved. See [artifact evidence and hashes](../verification/v0.1.0.md#inspected-artifacts-and-attribution).

Obtain an independent GitHub clone of the published source candidate and matching remote CI; verify downloaded published artifacts and the missing physical-phone/reachable HTTPS flow before claiming release acceptance. No publication or production rollout occurred during this audit.

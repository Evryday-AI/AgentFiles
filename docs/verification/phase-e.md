The subprocess harness imports `dist/server` compiled by the real production build and sets `nodeEnv=production`; no runtime fault endpoint or production source patch is added. Existing dependency seams pause after real staging or real finalization/pre-metadata, and after durable claim/pre-unlink or real unlink/pre-finalization. The parent externally kills the process (`SIGKILL` request maps to process termination on Windows), waits for termination and starts a new process. This is actual process death, not a controlled error/exit. The four windows do not establish power-loss/fsync durability or Linux container hard-kill behavior. Fixture-only maintenance scheduling allows pending-claim denials to be checked before invoking the same compiled production maintenance job.

Upload restart recounts abandoned bytes, then aging only the known owned leftover beyond grace lets maintenance reclaim it while a durable unrelated file survives. Deletion restart preserves the same claim UUID, denies metadata/download/share with 410 and keep with 409, confirms physical absence before finalization, preserves unrelated bytes and produces the same measured capacity after a second tick. Keep-first captures an actual compiled expiry candidate at a fixture future time before authenticated keep; stale cleanup cannot claim it after keep commits. Delete-first pauses after a committed claim and rejects keep before completing deletion. Existing Phase-C real pinned-client lock tests also pass in the full suite.

The ENOSPC case injects a disk-write error after real staging and verifies 507, no allocation and reclaimed bytes. It is not an actual filled filesystem, host disk exhaustion, process crash or power-loss test. No host disk filling/pruning occurs.

Backup checks the explicitly selected project/services/exact named-volume identities, stops/drains app plus in-process maintenance, then captures the complete dedicated DB and exact bytes while stopped. Registry and pending claims are included. Failure to archive a synthetic unreadable file rejects the snapshot and resumes a previously running app in `finally`; originally stopped apps remain stopped. A killed helper cannot execute `finally`, and the operator must inspect source state. [Backup instructions](../backups.md) require external-writer exclusion and encrypted private configuration/key recovery; labels alone cannot prove exclusive SQL credentials.

Current restore uses new owned DB/storage volumes and a new session secret, rejects old cookies, checks known bytes, resumes the same pending claim and denies restored expired content. A mismatched marker refuses startup. Without complete later-code evidence, upload returns `503 FILE_ISSUANCE_DISABLED`. The runner controls every later synthetic issuance and takes the surviving source's full quiesced code-only boundary, including a code whose file details were purged. It attests coverage privately, transactionally inserts the union without deleting restored reservations, then explicitly enables the current runtime. The integration allocator is forced to collide with a permanent purged reservation and cannot resolve the old code to a replacement. Time/counts alone are never treated as coverage proof.

Experimental schema-2 upgrade takes a matched offline DB/archive snapshot, explicitly verifies the original synthetic volume/full history, applies immutable schema 4 and verifies ledger/hashes. Current startup refuses nonempty unpaired state before explicit offline pairing. Old migration rejects the newer ledger. Rollback restores matched DB and archived original bytes into **new** owned volumes after the upgraded fixture bytes were deliberately changed. The old binary boots briefly for authenticated read verification and is then stopped: it lacks permanent reservations/issuance-disable support and is not safe for resumed issuance. Supported current-schema stale-snapshot recovery separately preserves later reservations.

HTTPS uses a generated one-day local CA/leaf for reserved `agentfiles.invalid`, a loopback TLS proxy and real Chromium with trust restricted to that leaf's SPKI; no OS trust store is changed. A Node TLS request validates the CA and hostname. Browser login sets Secure/HttpOnly/SameSite cookies, app/proxy upload caps reject excess bytes, a partial request hits the proxy's accelerated 250 ms fixture timeout, spoofed forwarded headers are overwritten, and route-template logs contain no password/token/query/header/body. This demonstrates controlled local TLS behavior, **not** a physical phone, reachable public HTTPS, recommended production timeout performance, other browsers/architectures or a deployment. Those gates remain open.

All new staged source is reviewed with redacted generic-secret/private-literal checks. Dumps/registry evidence/config/keys remain runtime-only ignored data. The CI additions are prepared for exact-release-source verification after separately authorized publication; local execution is not remote CI or E3 acceptance.

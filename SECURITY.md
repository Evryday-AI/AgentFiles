# Security policy

Report vulnerabilities privately through [GitHub private vulnerability reporting](https://github.com/Evryday-AI/AgentFiles/security/advisories/new). Repository reporting was enabled and independently confirmed with GitHub's `GET /repos/Evryday-AI/AgentFiles/private-vulnerability-reporting` returning `enabled: true` on 2026-10-11. See [GitHub's reporting instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

Do not open a public issue or PR containing exploit details, credentials, cookies, share links, uploaded content or private installation paths/addresses. If GitHub reporting is unavailable, open a public issue asking for a private contact without vulnerability details; no alternate email has been approved. A private report should identify the tested revision, affected route/configuration, expected/observed behavior and minimal synthetic reproduction. Share sensitive evidence only within the private advisory.

AgentFiles remains in preparation and has no accepted installable release. Security fixes currently target the latest reviewed preparation source; there is no promise of support for earlier development snapshots. Maintainers will assess reports, coordinate fixes/disclosure with the reporter and update the policy when a supported release exists. No guaranteed response time is offered.

Short file codes require authentication. Public share URLs are bearer credentials: recipients can use them until expiry/revocation or their admission limit. Expiry/revocation blocks new transfers; it cannot retract delivered copies or a transfer already admitted. Persistence requires explicit policy and permission. Operators own TLS/proxy trust, volume/DB isolation, log rotation, private configuration and backup retention. Keep one app process and an exclusively owned byte volume; see [retention/recovery](docs/retention.md). External backups may retain expired files; there is no forensic-erasure or end-to-end-encryption claim.

Runtime high/critical and development/build critical dependency findings block release gates. Lower-risk exceptions require an owner, reason, date, expiry and reproduction evidence, with manual compatibility review. The contribution workflow requires redacted secret scans, synthetic auth/lifecycle/setup tests and reviewed third-party notices. A passing scanner does not replace code review or exact-release artifact inspection.
